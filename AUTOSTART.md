# Автозапуск DSH у Windows після входу

Це **окрема, необов'язкова** настройка для майбутнього перевіреного білда. Завдання Планувальника Windows у репозиторії немає: його створюють на власному ПК після перевірки точних версій пакунків, встановлення та успішного ручного запуску. Не встановлюй версії плагінів із вердиктом BLOCK і не використовуй автозапуск як спосіб обійти перевірку залежностей.

## Підготовка

1. Заверши безпечне встановлення та перевір вручну запуск `Start-Harness.ps1` на порту `3082`. Закрий вікно цього запуску перед перевіркою завдання, інакше порт буде зайнятий. Не створюй другого завдання для тієї самої копії.
2. Знайди **повний локальний шлях** до теки репозиторію на цьому ПК. У прикладах нижче заміни `C:\PATH\TO\REPO` на свій шлях. Після перенесення теки онови дію завдання; шлях не переноситься між комп'ютерами автоматично.
3. Використовуй власний звичайний обліковий запис Windows. Запуск після входу, на відміну від запуску до входу, не потребує записувати пароль у завдання. Облікові дані DSH вводь лише в його локальному інтерфейсі, а не в аргументах Планувальника.

## Створення завдання

1. Натисни `Win+R`, введи `taskschd.msc` і вибери **Створити завдання** (не «Створити просте завдання»).
2. На вкладці **Загальні** задай ім'я `DSH Preview 3082`, вибери **Виконувати лише для користувача, який увійшов у систему**. Не вмикай найвищі права і не вибирай `SYSTEM`.
3. На вкладці **Тригери** додай **Під час входу до системи** для свого користувача. За потреби ввімкни **Відкласти завдання на 30 секунд**. Це дає час на запуск профілю, але не гарантує готовність мережі.
4. На вкладці **Дії** вибери **Запустити програму** й заповни поля:

   - **Програма або сценарій:** `C:\Windows\System32\WindowsPowerShell\v1.0\powershell.exe`
   - **Аргументи:** `-NoProfile -ExecutionPolicy Bypass -File "C:\PATH\TO\REPO\Start-Harness.ps1" -Port 3082`
   - **Робоча тека (Start in):** `C:\PATH\TO\REPO` (без лапок).

   Це має бути шлях до **цієї копії**, а не до живого Preview чи чужого профілю. Скрипт сам задає `DSH_HOME` зі свого розташування і слухає тільки `127.0.0.1`.
5. На вкладці **Параметри** вибери **Якщо завдання вже виконується: не запускати новий екземпляр**. Вимкни **Зупинити завдання, якщо воно виконується довше ніж 3 дні**, бо сервер працює постійно. Якщо ноутбук повинен працювати від батареї, на вкладці **Умови** зніми обмеження запуску й роботи лише від мережі живлення.
6. Збережи завдання. Воно стартуватиме **після входу цього користувача**, а не до входу. Браузер завдання не відкриває. За такого режиму вікно PowerShell може залишатися відкритим, поки працює сервер; не закривай його, якщо хочеш зберегти сервер запущеним.

## Перевірка і керування

У PowerShell цього ж користувача:

```powershell
Get-ScheduledTask -TaskName 'DSH Preview 3082'
Start-ScheduledTask -TaskName 'DSH Preview 3082'
Get-ScheduledTaskInfo -TaskName 'DSH Preview 3082' | Select-Object LastRunTime, LastTaskResult
Test-NetConnection 127.0.0.1 -Port 3082 -InformationLevel Quiet
```

Якщо остання команда повернула `True`, порт доступний. Потім відкрий `http://127.0.0.1:3082` і перевір потрібну сторінку зі **своєю** авторизацією: `True` або HTTP 200 самі по собі не доводять працездатність агента. Відповідь `401` без авторизації сама по собі не означає, що сервер не стартував. Не публікуй URL авторизації чи серверні журнали: вони можуть містити токени.

Для вимкнення наступних запусків:

```powershell
Disable-ScheduledTask -TaskName 'DSH Preview 3082'
```

Вимкнення завдання **не зупиняє вже запущений сервер**. Якщо ручний старт повідомляє про зайнятий порт, спершу визнач, який процес його слухає; не заверши чужий Preview навмання. Якщо завдання завершилося помилкою, переглянь **Історію** та **Результат останнього запуску** в Планувальнику, перевір шлях, встановлений runtime, права поточного користувача і зайнятість порту. У цього білда немає власної обгортки для повтору після падіння: не вважай, що Windows автоматично підніме сервер знову.

- У локально перевіреній іншій інсталяції Preview запуск після входу, заборона дублювання та окрема перевірка порту спрацювали. Планувальник **не виконав** очікуваний повтор після падіння в контрольному тесті; там знадобилася власна обгортка. Цей менший дистрибутив такої обгортки не містить, тому тут документовано лише автозапуск, а не автоматичне відновлення. Жодні особисті сесії, шляхи, ключі чи завдання Windows сюди не перенесено.
