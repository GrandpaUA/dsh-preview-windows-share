# План встановлення середовища для нового клієнта (Windows)

Цей план дає клієнту робочий DSH Preview із перевіреним набором плагінів і налаштувань. Одна команда встановлення, без ручного додавання плагінів. Ключі, чати й особисті дані не переносяться — клієнт додає власні облікові дані після запуску.

## Що клієнт отримає

- DSH Preview 0.2.0-rc.2 (офіційний рантайм, зафіксований lockfile).
- Плагіни з коробки: `dock-base`, `@dshthemes/ui` (тема cobalt2), локальні `dsh-locale-uk` (українська локаль), `dsh-wide-chat`, `dsh-headroom` (стиснення контексту), `dsh-codex-failover` (перемикання між двома акаунтами при вичерпанні квоти).
- Налаштування: українська локаль, темна тема, пресет агента `light`, типовий доступ `workspace-write` з підтвердженням дій, автоматичні заголовки сесій вимкнені, `ccr.persist: false`.
- Локальний вебінтерфейс на `127.0.0.1:3082`.

## Покроково для клієнта

1. Встановити з офіційних сайтів: [Node.js 22+](https://nodejs.org/), Git, потім у терміналі: `npm install -g pnpm@11.25.0`.
2. Отримати цей репозиторій (клон з приватного GitHub або копія теки — на вибір власника).
3. У PowerShell у теці репозиторію виконати:
   ```powershell
   powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\install.ps1
   ```
   Інсталятор сам: перевірить файли на секрети (`verify-release.ps1`), створить локальний профіль із шаблону, встановить рантайм і вебпрофіль із зафіксованих lockfile і запустить DSH на `127.0.0.1:3082`. Для встановлення без запуску — `install.ps1 -NoStart`.
4. Відкрити `http://127.0.0.1:3082` у браузері та додати **власні** ключі/акаунти провайдерів в інтерфейсі. Для failover-плагіна потрібні два акаунти ChatGPT (змінні `CODEX_CHATGPT_TOKEN` і `CODEX_CHATGPT_TOKEN_2` задає сам клієнт).
5. Наступні запуски — `Start-Harness.ps1` (порт за замовчуванням 3082, `-Port <n>` для іншого).

За потреби після перевірки версій пакетів і ручного запуску налаштуй [автозапуск після входу в Windows](AUTOSTART.md). Завдання Планувальника не входить до білда і не переноситься з іншого ПК; автоматичного відновлення після збою цей набір не обіцяє.

Жодних плагінів по одному встановлювати не треба: усі шість уже в маніфесті профілю й ставляться інсталятором.

## Чого в наборі немає і чому

П'ятнадцять плагінів із вихідного списку свідомо не включені:

За підтвердженням власника, в оригінальній збірці були встановлені ці шість плагінів. Їхніх назв немає в маніфесті цього набору:

- `@dennisrongo/dsh-memory`
- `@michengai/dsh-archive-manager`
- `dock-editor`
- `dsh-config-manager`
- `dsh-plugin-gate`
- `dshmarket`

- **Шість із вердиктом BLOCK** (`dsh-memory`, `dsh-archive-manager`, `dock-editor`, `dsh-config-manager`, `dsh-plugin-gate`, `dshmarket`) — статична перевірка знайшла високоризикові шаблони в цих точних версіях. Вони додаються лише коли видавець випустить нову версію, що пройде перевірку. Повний список із версіями — у `PLUGIN-HANDOFF.md`.
- **Дев'ять із WARN** (`dsh-usage`, `ultra-slash`, `dock-files`, `dock-git`, `checkpoint-diff`, `checkpoint-rewind`, `classic-coding`, `auto-continue`, `dsh-context`) — працездатні, але мають ризикові можливості (доступ до облікових даних, довільні шляхи, фонові запити). Їх можна додати пізніше за бажанням клієнта: спочатку переглянути знахідки сканера для точної версії, потім додати в `profiles/web/package.json` і оновити lockfile.

## Якщо середовище збирає інший агент

Почни з `AGENTS.md` у корені репозиторію — там повний порядок роботи, правила перевірки пакетів і межі доступу. Не обходь вердикти сканера, не копіюй секрети, не публікуй без дозволу власника.

## Перевірка цього плану

План фактично прогнано двічі: в ізольованій копії кандидата і в **чистому клоні з Git** (41 файл, без node_modules і без згенерованого профілю в клоні). Обидва рази: `verify-release.ps1` — PASS; генерація локального профілю — успішно; `pnpm install --frozen-lockfile` для рантайму (529 пакетів) і вебпрофілю (6 залежностей, включно з 4 локальними плагінами) — успішно; запуск — сервер на `127.0.0.1:3082`, головна сторінка HTTP 200 із маркером `__DSH_BOOT__`, без токена — 401. Залишилося перевірити на машині клієнта.
